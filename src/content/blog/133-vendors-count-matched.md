An accountant used AI to build something he did not have time to build by hand. The story would be forgettable without its last step: he checked that the count matched.

It is one practitioner's account, published in a newsletter. Treat it as a worked example, not as a pattern.

## What he did

The Rundown AI published the account in its 27 August 2026 issue, in a section of workflows from its community. Brian Carey runs a boutique accounting practice. One of his clients, a biotech company, needed a standardised document management system in SharePoint, and Carey did not have time to build it by hand.

He took the client's vendor list out of QuickBooks. He used Perplexity's Computer agent to clean the vendor names with a script. He then deployed the folder structure to OneDrive.

## What came out

The result was 133 vendor folders and 1,463 subfolders. It also included 13 "START HERE" guide files, a tagging taxonomy and naming standards. Carey described the last step as dragging everything to OneDrive, after which the count matched exactly.

Notice what this is. It is a folder structure that would not have existed otherwise. Nobody's job changed, and no person lost work to it.

## The step that matters

The count is the point. Carey can state "133 vendors, 1,463 subfolders" with confidence because he compared the output with the input. Without that comparison, the numbers would be whatever the script said they were.

Anyone who has trusted a spreadsheet formula knows the risk. A script can run without errors and still drop a row, duplicate a name or merge two vendors. Silence from the tool does not mean the result is right.

This is a plain act of verification. It needs no technical knowledge, only the habit of asking whether the end matches the start.

## What a check can look like

The simplest check is a count. Compare the number of items going in with the number coming out. If they differ, find out why before anyone relies on the result.

A second check is a spot sample. Pick five items at random and look at each one by hand. If all five are right, confidence rises. If one is wrong, you have found something worth knowing.

A third check is a rule. For example, no two vendors share a folder name, and every folder has a guide file. Rules like these are quick to write and catch a surprising number of faults.

## Why this example fits non-technical work

The account involves accounting, not software. The task was reconciliation: a list of things on one side and a structure on the other. Many managers run work with the same shape, such as client files, supplier records, staff documents or project folders.

It also describes work that would otherwise not have been done. A busy practice rarely finds a spare day to rebuild a document system. That is a more modest and more honest claim than "AI saved hours".

## What the account leaves out

Carey does not say how long the job took. He does not give a cost, or a comparison with building it by hand. Do not supply any of those yourself.

The client is described only as a biotech company, so nothing about it can be checked. The Rundown published the account, and nobody has audited it. One accountant doing one job is a single data point.

I also do not know how Carey checked beyond the count. He may have done more. The piece reports only that the count matched.

## What to do this month

**Pick one tidy-up job that has waited a long time.** A folder structure, a supplier list or a set of client files. Choose work where the result can be counted.

**Write the check before you start.** State what the end result should contain. For example, the number of vendors in the source list.

**Run the job, then run the check.** Compare the count first. Then look at five items by hand.

**Record what the check found.** Even a clean result is worth a note, because it tells you how far to trust the next job.

## Why the check gets skipped

The check is easy to skip because the result looks finished. A tidy folder tree, a clean table or a polished summary looks right at a glance. The moment of delivery feels like the end of the job, so the check feels like extra work.

It helps to treat the check as part of the job. Build it into the task before you start, the way you would agree a deadline. That turns it from an optional extra into a step with its own place in the plan.

It also helps to keep the check small. Nobody needs a long audit for a folder structure. A count and a five-item sample take a few minutes, and they catch the faults that matter most.

## What this is not

It is not a claim that AI can run a document system unsupervised. Carey chose the job, supplied the source list and ran the check. The tool did the repetitive middle, and a person owned both ends.

That division is worth copying. Decide what goes in, let the tool do the volume, and keep a person responsible for confirming what comes out.

## The takeaway

The tool did the building. The count made the result trustworthy. Whatever you ask AI to produce, decide in advance how you will check it.
